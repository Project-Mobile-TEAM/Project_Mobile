<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Navigation Deep Link `utechat://chat/direct/{peerUserId}` -> `ChatRoomFragment` | Deep link passes untrusted `peerUserId` string across graphs; server still checks `BLOCKED` and `CONTACT_REQUIRED` via `openOrCreateDirect`. |
| User Phone Input in `NewChatFragment` -> `ContactsRepository` Lookup | User enters arbitrary phone string; must normalize to E.164 and reuse Phase 4 lookup/rate-limit rules rather than bypassing them. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-21 | Information Disclosure | `ChatListFragment`, `GlobalSearchAdapter` | medium | mitigate | Label message results explicitly as "Tin nhắn trên thiết bị" / "On-device messages" and query strictly via `ChatRepository.searchGlobalMessages` (which enforces `visibleFromMessageId` and current user scope); clear search/view state on session change. |
| T-05-22 | Spoofing / Tampering | `ChatNavigation`, `MainActivity` | medium | mitigate | Deep link carries only `peerUserId` UUID (never JWT/credentials); `MainActivity` disconnects WS and cancels `"send-messages"` immediately upon `SessionEvents.expired()` or logout. |
</threat_model>
