# Plan 05-02: Backend Group Chat, SYSTEM Messages, Strict Visibility, Atomic Admin Handover & Receipts

<objective>
Expand the proven Wave 1 Backend messaging core to deliver complete Group Chat lifecycle management, server-authoritative `SYSTEM` messages (`systemEvent` + `systemParams`), strict per-tenure history isolation (`visible_from_message_id`), atomic `ADMIN` handover on leave/purge, read-only ejection (`NOT_A_MEMBER`), and monotonic receipt watermarks (`DELIVERED` / `READ`).

Purpose: Guarantee all group authorization, visibility, `ADMIN` continuity, and receipt invariants at the PostgreSQL transaction level before adding WebSocket/`/sync` (`05-03`) and Android clients (`05-04`+).
Output: Extended `ConversationService`, `MessageService`, `ConversationController`, `AccountService`, new `ReceiptService`, and comprehensive `GroupChatApiTest` on `EmbeddedPostgres`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated user -> Group Admin / Member endpoints | Caller passes `title`, `memberIds[]`, `userId`, `successorUserId`, `role`, `upToMessageId`; non-admins, non-members, or former members (`left_at != NULL`) must be denied server-side. |
| Scheduler thread (`AccountService.purgeExpiredDeletions`) -> PostgreSQL MVCC horizon | Long-running batch deletion transaction would pin `pg_snapshot_xmin` and stall `/api/sync`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Elevation of Privilege | `ConversationService` (`rename`, `addMembers`, `removeOrLeave`, `updateRole`) | high | mitigate | Lock `conversations FOR UPDATE`; require `left_at IS NULL` (`403 NOT_A_MEMBER`) and `role = 'ADMIN'` (`403 NOT_ADMIN`) derived from `AuthenticatedActor.userId()`, never request body. |
| T-05-06 | Tampering / History Leak | `ConversationService.addMembers`, `MessageService.getMessages` | high | mitigate | Compute `visible_from_message_id` strictly on server before `MEMBER_ADDED` `SYSTEM` insert; filter all message/conversation queries with strict `id > visible_from_message_id` and `left_at IS NULL`. |
| T-05-07 | Denial of Service / State Corruption | `ConversationService.removeOrLeave`, `AccountService.purgeExpiredDeletions` | medium | mitigate | Lock pair advisory locks in sorted UUID order when checking friends; disallow sole-ADMIN leaving/demoting without successor (`409 ADMIN_HANDOVER_REQUIRED`); purge each expired user in its own short `TransactionTemplate` transaction with auto-succession. |
</threat_model>
