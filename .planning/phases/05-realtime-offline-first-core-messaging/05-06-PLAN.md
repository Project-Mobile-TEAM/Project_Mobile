<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App Process -> Android WorkManager Persisted `Data` | WorkManager persists `Data` in its own internal SQLite DB; placing JWTs or plaintext message contents in `Data` would duplicate sensitive data outside `utechat.db`/Keystore. |
| Background Worker (`SendMessageWorker`) -> Active User Session | Device may log out or switch accounts while work is pending or an HTTP request is in flight. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-18 | Information Disclosure | `SendMessageWorker`, `RealChatRepository` | high | mitigate | Store ONLY `clientId` UUID in WorkManager `Data`; read message text from Room at execution time and check `meId.equals(msg.getSenderId())` + `sessionKey` before/after HTTP POST. |
| T-05-19 | Cross-Account Leakage / Replay | `RealAuthRepository`, `SendMessageWorker`, `Injection` | high | mitigate | On `logout`, `deleteAccount`, `401`, or WS `4401`, cancel only queueName(departingSessionKey), disconnect WS, and run `clearAllTables()` on shared `DISK` executor; on `401` inside `SendMessageWorker`, return `Result.failure()` after cancelling only queueName(enqueuedSessionKey); stale 401 must not expire the new session. |
| T-05-20 | Denial of Service (Queue Starvation) | `SendMessageWorker` | medium | mitigate | Return `Result.success()` (after saving `FAILED` + `errorCode`) for `400`/`403`/`404` and exhausted 3rd retry so WorkManager `APPEND_OR_REPLACE` continues draining queued messages for other conversations. |
</threat_model>
