<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted search query string -> SQLite FTS4 `MATCH` | User search input containing quotes, `AND`/`OR`/`NOT`/`NEAR`, `*`, `-`, `^`, `(`, `)`, or empty strings could throw `SQLiteException: malformed MATCH expression` if passed raw. |
| Late/cached server responses -> Room SQLite cache | Out-of-order history pages or late WS frames could re-insert messages `&lt;= visibleFromMessageId` or wipe local `SENDING`/`FAILED` rows (`serverId IS NULL`). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08 | Denial of Service / Query Injection | `MessageText.safeMatchQuery`, `MessageDao` | high | mitigate | Strip non-word punctuation via `[\\p{L}\\p{Nd}_]+` tokenization after NFD + `d/D` normalization, quote every token as `"token"*`, and return `null` on empty/punctuation-only queries so DAO search skips `MATCH`. |
| T-05-09 | Information Disclosure | `MessageDao`, `ConversationDao` | high | mitigate | Enforce `(m.serverId IS NULL OR m.serverId &gt; COALESCE(mb.visibleFromMessageId, 0))` in every visible query and FTS4 search, and purge `serverId &lt;= visibleFromMessageId` so SQLite triggers remove `message_fts` entries immediately. |
| T-05-10 | Tampering / Data Loss | `AppDatabase.MIGRATION_1_2`, `MessageDao.purgeBeforeVisibleId` | high | mitigate | Explicit `Migration(1, 2)` without destructive fallback preserves Phase 3/4 cached data; `purgeBeforeVisibleId` requires `AND serverId IS NOT NULL` to protect `SENDING`/`FAILED` messages. |
</threat_model>
