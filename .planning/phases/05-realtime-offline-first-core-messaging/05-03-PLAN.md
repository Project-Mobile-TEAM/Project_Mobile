# Plan 05-03: Backend WebSocket (/ws), Consistent Bootstrap Snapshot, Gap-Safe /api/sync & Retention

<objective>
Add Spring Boot WebSocket (`/ws`) pure-JSON realtime transport with strict Bearer handshake validation, `afterCommit()` dispatching shared across Chat and Contact events, `4401` immediate revocation/expiration closure, consistent `REPEATABLE READ` `GET /api/sync/bootstrap`, lock-free `barrier_xid` gap-safe `GET /api/sync` pagination (`410 SYNC_CURSOR_EXPIRED`), and daily 30-day retention cleanup.

Purpose: Deliver real-time push and mathematically gap-safe offline catch-up without global write locks, tested directly against `EmbeddedPostgres` and real Tomcat WebSocket connections.
Output: WebSocket package, `SyncService`, `SyncRetentionService`, `SyncController`, `afterCommit` `SyncEventWriter` wiring, `SyncAndBootstrapApiTest`, and `WebSocketAuthAndRealtimeTest`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External client HTTP Upgrade -> `/ws` | Client initiates WS Upgrade over TLS/HTTP; query params or unauthenticated upgrades could leak JWTs into proxy logs or bypass device checks. |
| Active WebSocket connection -> Revoked/Expired Session | Device can be revoked, password changed, or JWT expired while a long-lived WS connection remains open. |
| Client WS text frame -> `ChatWebSocketHandler` | Client sends `ping`, `typing.start`, `typing.stop`, or malformed JSON targeting arbitrary `conversationId`s. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-11 | Information Disclosure | `WsAuthHandshakeInterceptor` | critical | mitigate | Reject any `/ws` Upgrade containing query params `token`, `jwt`, `access_token`, `bearer`, or `authorization` (case-insensitive) with HTTP `400`; never log `request.getURI().getRawQuery()`. |
| T-05-12 | Elevation of Privilege / Stale Session | `WebSocketSessionRegistry`, `AccountService`, `AuthService`, `ChatWebSocketHandler` | high | mitigate | Attach `deviceRowId`, `issuedAtMs`, `tokenExpiresAt` during handshake; check DB active/not-revoked on app `ping` and 30s scheduled reaper; send `auth.revoked` and close `4401` immediately after commit on revoke/logout/password-reset/deletion. |
| T-05-13 | Information Disclosure / DoS | `ChatWebSocketHandler` (`typing`) | medium | mitigate | Validate `conversationId` UUID and verify active membership (`left_at IS NULL`) before forwarding `typing`; rate-limit `typing.start` to 1 frame per 3s per `(userId, conversationId)`; drop oversized/malformed frames safely. |
| T-05-14 | Repudiation / State Drift | `SyncService`, `SyncEventWriter` | high | mitigate | Query `barrier_xid <= pg_snapshot_xmin(pg_current_snapshot())` on both `/sync/bootstrap` and `/sync`; push WS frames strictly inside `TransactionSynchronization.afterCommit()`. |
</threat_model>
