<action>
1. Tạo thư mục `backend/scripts/` nếu chưa có.
2. Tạo tệp `backend/scripts/verify-schema.sql` với các truy vấn chẩn đoán chỉ đọc (read-only, idempotent) và có cột đánh giá trạng thái `PASS` / `FAIL` rõ ràng:
   - **Mục 1: Đếm số lượng bảng cốt lõi (Table Count Check):**
     Truy vấn `information_schema.tables` với schema `public`. Đếm đúng 14 bảng: `users`, `user_devices`, `otp_challenges`, `auth_sessions`, `auth_throttles`, `contact_requests`, `contacts`, `conversations`, `conversation_members`, `attachments`, `calls`, `messages`, `sync_events`, `demo_sms_outbox`. Đánh giá `PASS` khi `COUNT(*) >= 14`.
   - **Mục 2: Kiểm tra trạng thái Row Level Security (RLS Status Check):**
     Truy vấn `pg_class` và `pg_namespace` cho schema `public`. Kiểm tra thuộc tính `relrowsecurity = true` trên 100% các bảng. Đánh giá `PASS: RLS Enabled` nếu bật, `FAIL: RLS Disabled` nếu tắt.
   - **Mục 3: Kiểm tra rò rỉ Policy RLS (RLS Policies Lockdown Check):**
     Truy vấn `pg_policies` cho schema `public`. Đếm số lượng policy. Đánh giá `PASS: 0 Policies (Lockdown intact)` nếu số lượng = 0, `FAIL: Policies detected!` nếu có bất kỳ policy nào được mở.
   - **Mục 4: Kiểm tra sự tồn tại của các chỉ mục then chốt (Index Check):**
     Kiểm tra các chỉ mục: `idx_contact_requests_pending_pair`, `idx_messages_conversation_id_desc`, `idx_sync_events_user_cursor`, `idx_users_phone`, `idx_auth_throttles_scope`.
   - **Mục 5: Kiểm tra cột quyền riêng tư và ràng buộc CHECK (Privacy & Invariants Check):**
     - Cột `users.allow_messages_from_non_contacts` kiểu `boolean` và `NOT NULL`.
     - Ràng buộc `chk_watermarks_monotonic` trên `conversation_members`.
     - Ràng buộc `chk_contact_requests_no_self` trên `contact_requests`.
   - **Mục 6: Kiểm tra số lượng bản ghi dữ liệu mẫu (Seed Data Verification):**
     Đếm số dòng:
     - `users`: đúng 5 người dùng (`Alice`, `Bob`, `Charlie`, `David`, `Eve`).
     - `contacts`: ít nhất 7 dòng (3 cặp bạn bè 2 chiều = 6 dòng + 1 dòng Alice chặn Eve = 7 dòng).
     - `contact_requests`: ít nhất 1 lời mời `PENDING` (Bob -> David).
     - `conversations`: ít nhất 2 hội thoại (1 DIRECT Alice-Bob và 1 GROUP 3 người).
     - `conversation_members`: ít nhất 5 dòng thành viên.
     - `messages`: ít nhất 3 tin nhắn mẫu.
     - `sync_events`: ít nhất 3 bản ghi sự kiện đồng bộ.
</action>

</read_first>

<action>
1. Tạo tệp script PowerShell `backend/scripts/test-db-connection.ps1`.
2. Hỗ trợ các tham số:
   - `-Quick`: Chạy nhanh kiểm tra cú pháp cấu hình và kiểm tra kết nối mạng cơ bản.
   - `-Full`: Chạy toàn bộ các bước kiểm tra (Network Ping, PostgREST API lockdown, kiểm tra tệp schema).
   - `-EnvFile <path>`: Đường dẫn tệp môi trường (mặc định `.env`, fallback sang `.env.example` nếu `.env` chưa có).
3. Nội dung thực thi của script:
   - **Bước 1: Nạp cấu hình môi trường:**
     Đọc tệp môi trường, phân tách các biến `DB_HOST`, `DB_PORT_SESSION`, `DB_PORT_TRANSACTION`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SPRING_DATASOURCE_URL`.
     Kiểm tra hợp lệ: nếu phát hiện `prepareThreshold=0` trong JDBC URL thì báo `[PASS] prepareThreshold=0 configured`.
   - **Bước 2: Kiểm tra kết nối TCP mạng tới Supabase (Network Reachability Check):**
     Nếu có cấu hình `DB_HOST`:
     Sử dụng `Test-NetConnection -ComputerName $host -Port 5432` và `Test-NetConnection -ComputerName $host -Port 6543`.
     Báo cáo kết quả kết nối và độ trễ phản hồi (Latency).
   - **Bước 3: Kiểm tra khóa bảo mật PostgREST (PostgREST RLS Lockdown Verification):**
     Nếu có `SUPABASE_URL` và `SUPABASE_ANON_KEY`:
     Thực hiện gọi HTTP GET tới `$SUPABASE_URL/rest/v1/users` kèm header `apikey: $SUPABASE_ANON_KEY` và `Authorization: Bearer $SUPABASE_ANON_KEY`.
     - Nếu trả về status 200 và mảng rỗng `[]`: Báo `[PASS] PostgREST Public Data API is strictly locked down (0 records accessible)`.
     - Nếu trả về HTTP 401 hoặc 403: Báo `[PASS] PostgREST rejected unauthorized access as expected`.
     - Nếu trả về dữ liệu người dùng (> 0 records): Báo `[FAIL] SECURITY BREACH: PostgREST exposed user data! Check RLS configuration!`.
   - **Bước 4: Kiểm tra tệp DDL migration và verification script:**
     Xác nhận sự tồn tại của `V1__initial_schema.sql`, `V2__seed_demo_data.sql`, và `verify-schema.sql`.
   - **Tổng kết:**
     In ra bảng tóm tắt kết quả kiểm tra với mã thoát (exit code 0 nếu tất cả hợp lệ, exit code 1 nếu có lỗi).
</action>

<acceptance_criteria>

- Script hỗ trợ tham số `-Quick` và `-Full`.
