<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Delayed `/sync` / `SyncWorker` callback -> `NotificationHelper` | User may log out or switch accounts while a background HTTP `/sync` or `SyncWorker` run is finishing. |
| OS Notification Shade -> `MainActivity` PendingIntent | Tapping a grouped notification opens `ChatRoomFragment`; PendingIntent must use `FLAG_IMMUTABLE` and explicit component targeting (`MainActivity`) so external apps cannot hijack extras. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-15 | Information Disclosure (Cross-Account Notification Leak) | `NotificationHelper`, `SyncEngine`, `SyncWorker` | high | mitigate | Verify `sessionKey.equals(session.sessionKey())` BEFORE building/posting notifications; wipe all OS notifications via `cancelAll()` on logout/401/4401/account switch; suppress bootstrap snapshot notifications. |
| T-06-16 | Tampering (PendingIntent Hijack) | `NotificationHelper` | medium | mitigate | Construct explicit `Intent(context, MainActivity.class)` with `PendingIntent.FLAG_UPDATE_CURRENT | PendingIntent.FLAG_IMMUTABLE` (required on `targetSdk = 36`). |
| T-06-17 | Integrity (Cursor Race) | `SyncWorker`, `SyncEngine.syncBlocking` | medium | mitigate | Share `SyncEngine`'s `running` / `resyncRequested` single-flight mutex and `runOnePass()` transaction boundary so `SyncWorker` never races WS/foreground `sync_state` writes. |
</threat_model>
