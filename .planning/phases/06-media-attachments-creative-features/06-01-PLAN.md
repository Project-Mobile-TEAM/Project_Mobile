<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted Android client -> `MediaController` / `MessageController` | Client supplies multipart file bytes, `kind`, original filename, `Content-Type`, `Range` header, `mediaUrl`, `latitude`, `longitude`. Identity comes strictly from `@AuthenticationPrincipal AuthenticatedActor`. |
| `MediaService` -> Local Server Filesystem (`MEDIA_STORAGE_DIR`) | Raw client filenames or path segments could cause path traversal or overwrite server files if interpolated into disk paths. |
| Backend JDBC -> Supabase `public` Schema (`V6`) | Altered `calls` and `messages` tables sit in `public` schema exposed to Supabase PostgREST unless `ENABLE ROW LEVEL SECURITY` with zero public policies stays preserved. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Spoofing / Tampering (Path Traversal & Malicious Upload) | `MediaService.storeUpload`, `GlobalExceptionHandler` | high | mitigate | Ignore client `originalFilename` in disk paths (`<yyyy>/<MM>/<uuid><safeExt>`); verify `target.normalize().startsWith(rootDir.normalize())`; inspect magic bytes regardless of `Content-Type` (reject SVG/HTML/EXE/ELF/APK -> `415 UNSUPPORTED_TYPE`); enforce streaming byte caps + `MaxUploadSizeExceededException` -> `413 FILE_TOO_LARGE`; serve downloads with `X-Content-Type-Options: nosniff`. |
| T-06-02 | Information Disclosure (IDOR / Pre-join Media Leak / Token in URL) | `MediaController.downloadMedia`, `MediaService.prepareDownload` | high | mitigate | Authenticate solely via `Authorization: Bearer` header (reject query tickets); enforce `left_at IS NULL AND message.id > visible_from_message_id` for message-linked attachments or `uploader_id == actorId` for unattached uploads (`403 FORBIDDEN` otherwise). |
| T-06-03 | Tampering (Cross-User Attachment Hijack) | `MessageService.sendMessage` | high | mitigate | Parse `attachmentId` strictly from `/api/media/{uuid}`, lock `attachments` row `FOR UPDATE`, verify `uploader_id == actorId` (`403 FORBIDDEN`), `kind == req.type()` (`400 VALIDATION`), and rely on `uq_messages_attachment` (`409 CONFLICT` on reuse). |
| T-06-04 | Denial of Service | `MediaUploadRateLimiter`, `MediaController.downloadMedia` | medium | mitigate | Sliding-window rate limit `20 uploads / 60s / userId` (`429 RATE_LIMITED`); stream `Range` slices via `FileChannel` without buffering 50MB files into heap; reject malformed/multi-range headers with `416 Range Not Satisfiable`. |
</threat_model>
