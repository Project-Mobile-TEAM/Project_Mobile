# Plan 02-03: Android Single Activity, Nested Nav Graphs, Resources & End-to-End Health Probe

## Mục tiêu
Hiện thực hóa toàn bộ các điểm nóng còn lại của Kiến trúc chống xung đột (Hotspot 1, 2, 3, 4) và hoàn tất đầu dò Walking Skeleton End-to-End: Khóa cấu hình Gradle và An ninh Mạng Android; phân vùng tài nguyên chuỗi đa ngôn ngữ (EN và VI); triển khai kiến trúc Pure Single Activity với `MainActivity` và 3 tab `BottomNavigationView`; cấu hình Nested Navigation Graphs (`<include>`) kèm 4 stub fragments; và xây dựng tầng Networking Retrofit kết nối tới backend Spring Boot để `SplashFragment` hiển thị huy hiệu trạng thái kết nối máy chủ / CSDL theo thời gian thực.

1. Cập nhật `app/build.gradle.kts`:
   - Bổ sung vào `defaultConfig`:
     - `buildConfigField("String", "BACKEND_BASE_URL", "\"http://10.0.2.2:8080/\"")`
     - `buildConfigField("boolean", "USE_FAKE_DATA", "true")`
     - `javaCompileOptions { annotationProcessorOptions { arguments += mapOf("room.schemaLocation" to "$projectDir/schemas") } }`
   - Chú thích Tiếng Việt giải thích vai trò của từng biến môi trường.

2. Tạo `app/src/main/res/xml/network_security_config.xml`:
   - Cấu hình `<domain-config cleartextTrafficPermitted="true">` cho `10.0.2.2`, `localhost`, `127.0.0.1`.
   - Cấu hình `<base-config cleartextTrafficPermitted="true">` với trust-anchors hệ thống cho môi trường dev.
   - Thêm chú thích Tiếng Việt giải thích lý do Android 9+ chặn cleartext HTTP và cảnh báo không dùng cú pháp CIDR.

3. Cập nhật `app/src/main/AndroidManifest.xml`:
   - Bổ sung thuộc tính `android:networkSecurityConfig="@xml/network_security_config"` và `android:usesCleartextTraffic="true"` vào thẻ `<application>`.
   - Đảm bảo quyền `android.permission.INTERNET` và `android.permission.ACCESS_NETWORK_STATE` đã khai báo.

     - `strings_contacts.xml`: Chuỗi danh bạ (`title_contacts`, `hint_search_phone`, `btn_add_friend`, `label_blocked`).
     - `strings_profile.xml`: Chuỗi hồ sơ (`title_profile`, `label_name`, `btn_logout`, `switch_stranger_messages`).
   - Trong `app/src/main/res/values-vi/`:
     - Tạo bộ 5 tệp tương ứng (`strings_common.xml`, `strings_auth.xml`, `strings_chat.xml`, `strings_contacts.xml`, `strings_profile.xml`) với nội dung bản địa hóa tiếng Việt chuẩn xác.
   - Giữ lại hoặc làm rỗng an toàn `strings.xml` gốc để không gây xung đột trùng lặp key chuỗi.

5. Tạo các icon vector drawable trong `app/src/main/res/drawable/`:
   - `ic_tab_chat.xml`: Biểu tượng tin nhắn hội thoại.
   - `ic_tab_contacts.xml`: Biểu tượng danh bạ bạn bè.
   - `ic_tab_profile.xml`: Biểu tượng cá nhân / hồ sơ.

6. Tạo menu điều hướng `app/src/main/res/menu/bottom_nav_menu.xml`:
   - 3 items: `@+id/nav_chat` (title `@string/tab_chat`), `@+id/nav_contacts` (title `@string/tab_contacts`), `@+id/nav_profile` (title `@string/tab_profile`).
   - Chú thích Tiếng Việt nhấn mạnh ID item bắt buộc phải trùng 100% với ID của đồ thị điều hướng con.

7. Tạo 4 Stub Fragments và layout XML tương ứng:
   - `com.utechat.ui.auth.LoginFragment` kèm `res/layout/fragment_login.xml`.
   - `com.utechat.ui.chat.ChatListFragment` kèm `res/layout/fragment_chat_list.xml`.

   - Sử dụng ViewBinding trên toàn bộ các Fragment stub, giải phóng binding tại `onDestroyView()`.

8. Cấu hình Nested Navigation Graphs (Hotspot 3) trong `app/src/main/res/navigation/`:
   - `nav_auth.xml`: Root `<navigation android:id="@+id/nav_auth" app:startDestination="@id/loginFragment">`, chứa `LoginFragment`.
   - `nav_chat.xml`: Root `<navigation android:id="@+id/nav_chat" app:startDestination="@id/chatListFragment">`, chứa `ChatListFragment`.
   - `nav_contacts.xml`: Root `<navigation android:id="@+id/nav_contacts" app:startDestination="@id/contactsListFragment">`, chứa `ContactsListFragment`.
   - `nav_profile.xml`: Root `<navigation android:id="@+id/nav_profile" app:startDestination="@id/profileFragment">`, chứa `ProfileFragment`.
   - `nav_graph.xml`: Root graph chứa `SplashFragment` (`@id/splashFragment`, startDestination), có 2 actions `action_splash_to_auth` và `action_splash_to_main` (đều có `popUpTo="@id/splashFragment"` và `popUpToInclusive="true"`), và nhúng 4 đồ thị con qua thẻ `<include app:graph="@navigation/..." />`.

9. Cập nhật giao diện chính `app/src/main/res/layout/activity_main.xml`:

10. Cập nhật `app/src/main/java/com/utechat/MainActivity.java`:

    - Nạp `ActivityMainBinding`.
    - Kết nối `NavigationUI.setupWithNavController(binding.bottomNav, navController)`.
    - Đăng ký `navController.addOnDestinationChangedListener(...)`: chỉ hiển thị `binding.bottomNav` khi `destination.getId()` là `R.id.chatListFragment`, `R.id.contactsListFragment`, hoặc `R.id.profileFragment`; ẩn `View.GONE` tại tất cả các màn hình còn lại (Splash, Auth, Detail).
    - Thêm chú thích Tiếng Việt chi tiết cho toàn bộ code.

   - Phương thức: `@GET("api/health") Call<HealthDto> getHealth();`.

   - Khởi tạo Retrofit instance trỏ tới `BuildConfig.BACKEND_BASE_URL` với `GsonConverterFactory.create()`.
   - Cung cấp phương thức tĩnh `public static Retrofit getRetrofit()`.
   - Chú thích Tiếng Việt giải thích cấu hình timeout cho mạng di động.

4. Tạo kho dữ liệu kiểm tra sức khỏe `app/src/main/java/com/utechat/data/repository/HealthRepository.java`:

   - Phương thức `public void checkHealth(HealthCallback callback)`: Thực thi `apiService.getHealth().enqueue(...)` bất đồng bộ, phản hồi kết quả về UI thread hoặc callback thích hợp.
   - Cập nhật `Injection.java` để cung cấp `HealthRepository` thông qua `provideHealthRepository()`.

5. Tạo `app/src/main/java/com/utechat/ui/splash/HealthViewModel.java`:
   - Kế thừa `ViewModel`. Nhận `HealthRepository` qua constructor.
   - Định nghĩa enum `public enum ProbeStatus { LOADING, SUCCESS, ERROR }`.
   - `LiveData<ProbeStatus> getStatus()`, `LiveData<HealthDto> getHealthData()`, `LiveData<String> getErrorMessage()`.
   - Phương thức `public void checkHealth()` và `public void retry()`.
   - Cập nhật `ViewModelFactory.java` hỗ trợ khởi tạo `HealthViewModel`.

6. Tạo layout giao diện màn hình chào `app/src/main/res/layout/fragment_splash.xml`:
   - Logo UTEChat và tên ứng dụng nổi bật theo chuẩn Material 3.
   - `ProgressBar` tròn hiển thị trong trạng thái đang kiểm tra (`LOADING`).
   - Cụm huy hiệu (Badges) hiển thị kết quả kiểm tra hệ thống:

   - Nút **"Thử lại"** (`btn_retry`) xuất hiện khi kết nối thất bại.
   - Nút **"Tiếp tục chế độ Offline"** (`btn_continue_offline`) cho phép bỏ qua kiểm tra mạng để vào thẳng giao diện mà không bị nghẽn luồng.

7. Tạo `app/src/main/java/com/utechat/ui/splash/SplashFragment.java`:

   - Khởi tạo `HealthViewModel` qua `ViewModelFactory`.
   - Đăng ký quan sát LiveData:
     - Khi `ProbeStatus.LOADING`: Hiển thị ProgressBar, ẩn cụm nút thử lại.

   - Bắt sự kiện bấm nút `btn_retry` gọi `viewModel.retry()`.
   - Bắt sự kiện bấm nút `btn_continue_offline` điều hướng thẳng sang luồng Auth.
   - Giải phóng ViewBinding trong `onDestroyView()` để triệt tiêu rò rỉ bộ nhớ.
   - Thêm chú thích Tiếng Việt chi tiết trên mọi phương thức vòng đời Fragment.
