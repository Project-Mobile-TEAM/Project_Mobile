## 2. Backend Spring Boot 3 Patterns (`com.utechat.backend`)

### 2.1 Flyway `V9__message_actions_reactions_stickers.sql` & RLS Pattern
- **Phân loại:** *No analog (greenfield schema migration V9)*; đối chiếu quy chuẩn `CHECK` inline và RLS tại `V1__initial_schema.sql#L135,L154-L160,L188-L200` và `V7__two_factor.sql#L16-L22`.
- **Quy chuẩn bắt buộc:**
  1. Tên ràng buộc `CHECK` mặc định của PostgreSQL từ `V1`: `messages_type_check` và `sync_events_event_type_check` → `DROP CONSTRAINT IF EXISTS` rồi `ADD CONSTRAINT` mở rộng thêm `'STICKER'` và 3 event Phase 7.
  2. Mọi bảng mới (`sticker_packs`, `stickers`, `user_sticker_packs`, `message_deletions`, `message_reactions`) **bắt buộc** có `ALTER TABLE public.<name> ENABLE ROW LEVEL SECURITY;` và **không** tạo policy công khai (`ADR-007`, `DEPLOYMENT_SECURITY.md`).
  3. Bảng `public.attachments` thêm `revoked_at TIMESTAMPTZ` để vô hiệu hóa vĩnh viễn việc tải lại media của tin nhắn đã gỡ (`D-02`).
  4. Bảng `public.message_reactions` có `PRIMARY KEY (message_id, user_id)` và `CHECK (emoji IN ('❤️', '😂', '👍', '😮', '😢', '😡'))` để bảo đảm tối đa 1 cảm xúc/người/tin ở tầng DB (`D-06`).
  5. Dữ liệu seed 2 bộ mẫu (`ute_daily` `is_default = TRUE`, `ute_campus` `is_default = FALSE`, mỗi bộ 6 sticker) dùng UUID cố định và `ON CONFLICT ... DO NOTHING`.

### 2.2 Mẫu `MessageService` (Recall 24h với `Clock`, Delete for Me, Reactions 6 Emoji & `STICKER`)
- **Analog trực tiếp:** `MessageService.java#L25-L140` (khóa `FOR UPDATE`, `ContactPolicyService`, `SyncEventWriter`) và `MediaService.java#L67-L85` (tiêm `Clock` cho kiểm thử biên thời gian xác định).
- **Quy chuẩn triển khai:**
  ```java
  // Chuẩn hóa biến thể Unicode trái tim: "\u2764" -> "\u2764\uFE0F" ("❤️") trước khi kiểm tập 6 emoji cố định.
  private static final Set<String> FIXED_EMOJIS = Set.of("❤️", "😂", "👍", "😮", "😢", "😡");

  private static String normalizeEmoji(String raw) {
      if (raw == null || raw.isBlank()) return null;
      String trimmed = raw.trim();
      return "\u2764".equals(trimmed) ? "\u2764\uFE0F" : trimmed;
  }
  ```
  - **Recall (`recallMessage`):**
    1. Khóa dòng `messages` bằng `SELECT ... FROM public.messages WHERE id = ? AND conversation_id = ? FOR UPDATE`.
    2. Kiểm thành viên đang hoạt động (`left_at IS NULL`, sai → `403 NOT_A_MEMBER`), kiểm không bị chặn 2 chiều ở chat `DIRECT` (`403 BLOCKED`, `D-04`).
    3. Kiểm `sender_id.equals(actorId)` (sai → `403 FORBIDDEN`, kể cả group `ADMIN`, `D-01`).
    4. Chặn `SYSTEM` và `CALL` (`409 INVALID_STATE`). Nếu `recalled_at != null` → trả `200 OK` idempotent, không ghi trùng `sync_events`.
    5. Kiểm `Duration.between(createdAt, clock.instant()).compareTo(Duration.ofHours(24)) > 0` → ném `409 RECALL_EXPIRED`.
    6. Cập nhật `recalled_at = now(), text = NULL, attachment_id = NULL, latitude = NULL, longitude = NULL, sticker_id = NULL`; nếu có `oldAttachmentId` thì `UPDATE public.attachments SET revoked_at = now() WHERE id = ?` và đăng ký `TransactionSynchronization.afterCommit()` xóa file vật lý; xóa mọi dòng `message_reactions` của tin này; gọi `syncEvents.append(...)` phát `MESSAGE_RECALLED` cho toàn bộ thành viên `left_at IS NULL`.
  - **Delete for Me (`deleteMessageForMe`):**
    1. Kiểm `conversation_members` tồn tại cho `(conversationId, actorId)` **không** yêu cầu `left_at IS NULL` và **không** kiểm `BLOCKED` (`D-04`), nhưng vẫn kiểm `message.id > member.visible_from_message_id` (`404 NOT_FOUND`).
    2. `INSERT INTO public.message_deletions (user_id, message_id) VALUES (?, ?) ON CONFLICT DO NOTHING`. Nếu số dòng chèn `> 0`, phát `MESSAGE_DELETED_FOR_ME` **duy nhất** cho `actorId` (`D-03`).
  - **Reaction (`toggleReaction`):**
    1. Kiểm active member (`left_at IS NULL`), không bị chặn ở `DIRECT`, tin chưa bị xóa phía caller, không phải `SYSTEM` và `recalled_at IS NULL`.
    2. Chuẩn hóa emoji; nếu khác `null` mà không thuộc `FIXED_EMOJIS` → `400 VALIDATION`.
    3. Nếu `emoji == null` hoặc trùng `currentEmoji` → `DELETE` (`action = "REMOVED"`); ngược lại `INSERT ... ON CONFLICT (message_id, user_id) DO UPDATE SET emoji = EXCLUDED.emoji, created_at = now()` (`action = "SET"`). Chỉ phát `MESSAGE_REACTION_UPDATED` tới thành viên `left_at IS NULL` khi trạng thái thật sự thay đổi.

### 2.3 Mẫu `MediaService` Thu hồi Media & `ConversationService` Lùi Preview
- **Analog:** `MediaService.java#L280-L333` & `ConversationService.java#L617-L632`.

## 3. Android Data Layer & Room v4 Patterns (`com.utechat.data`)

### 3.1 Room `AppDatabase` v3 → v4 (`MIGRATION_3_4`) & FTS4 Invariant
- **Analog trực tiếp:** `AppDatabase.java#L14-L74` (`MIGRATION_1_2`, `MIGRATION_2_3`) và `AppDatabaseMigrationTest.java#L40-L100`.
- **Mẫu `MIGRATION_3_4` chuẩn xác:**
  ```java
  // Migration tường minh từ v3 lên v4 (Phase 7, D-13): thêm recalledAt và 3 bảng message_reaction, sticker_pack, sticker.
  public static final Migration MIGRATION_3_4 = new Migration(3, 4) {
      @Override
      public void migrate(@NonNull SupportSQLiteDatabase db) {
          db.execSQL("ALTER TABLE message ADD COLUMN recalledAt INTEGER");
          db.execSQL("CREATE TABLE IF NOT EXISTS `message_reaction` ("
                  + "`messageServerId` INTEGER NOT NULL, `userId` TEXT NOT NULL, "
                  + "`emoji` TEXT NOT NULL, `createdAt` INTEGER NOT NULL, "
                  + "PRIMARY KEY(`messageServerId`, `userId`))");
          db.execSQL("CREATE INDEX IF NOT EXISTS `index_message_reaction_messageServerId` "
                  + "ON `message_reaction` (`messageServerId`)");
          db.execSQL("CREATE TABLE IF NOT EXISTS `sticker_pack` ("
                  + "`packId` TEXT NOT NULL, `code` TEXT NOT NULL, `name` TEXT NOT NULL, "
                  + "`description` TEXT, `thumbnailUrl` TEXT NOT NULL, "
                  + "`installed` INTEGER NOT NULL, `isDefault` INTEGER NOT NULL, "
                  + "`sortOrder` INTEGER NOT NULL, PRIMARY KEY(`packId`))");
          db.execSQL("CREATE TABLE IF NOT EXISTS `sticker` ("
                  + "`stickerId` TEXT NOT NULL, `packId` TEXT NOT NULL, `code` TEXT NOT NULL, "
                  + "`label` TEXT NOT NULL, `imageUrl` TEXT NOT NULL, `localPath` TEXT, "
                  + "`width` INTEGER NOT NULL, `height` INTEGER NOT NULL, `sortOrder` INTEGER NOT NULL, "
                  + "PRIMARY KEY(`stickerId`))");
          db.execSQL("CREATE INDEX IF NOT EXISTS `index_sticker_packId` ON `sticker` (`packId`)");
      }
  };
  ```
- **Invariant FTS4:** Khi `MessageDao.markRecalledByServerId` đặt `text = NULL, normalized_text = NULL` hoặc `deleteByServerId` xóa dòng, trigger SQLite FTS4 của `MessageFtsEntity` tự động loại nội dung khỏi `message_fts`. Bổ sung thêm `AND m.recalledAt IS NULL` trong câu SQL tìm kiếm để phòng thủ 2 lớp.

### 3.2 Mẫu `SyncEventApplier`, `ChatWebSocketManager` & `SendMessageWorker`
- **Analog:** `SyncEventApplier.java#L276-L320`, `ChatWebSocketManager.java#L442-L450`, `SendMessageWorker.java#L294-L343`.
- **Quy tắc đồng bộ 1 chiều (`WS` → `/api/sync` → `Room`):**
  - `ChatWebSocketManager` nhận `message.recalled`, `message.deleted`, `message.reaction` → **chỉ** bật `shouldRequestSync = true` (tuyệt đối không sửa Room từ luồng WS).

    - `MESSAGE_RECALLED`: `markRecalledByServerId` + `translationDao.deleteAllForMessage(existing.getClientId())` + `reactionDao.deleteByMessageServerId(messageId)`.
    - `MESSAGE_DELETED_FOR_ME`: `deleteByServerId` + xóa reaction/translation + tính lại `conversation.lastMessageId`/`lastMessageAt` từ `messageDao.findLatestVisibleMessageSync(...)`.
    - `MESSAGE_REACTION_UPDATED`: `emoji == null` → `reactionDao.delete(messageId, userId)`; ngược lại `reactionDao.upsert(...)`.

### 3.3 Mẫu Bảo mật URL, Cache Sticker & Cô lập Phiên (`ApiClient`, `StickerCacheManager`, `Injection`)
