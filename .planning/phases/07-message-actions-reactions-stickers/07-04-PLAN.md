<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend `/api/sync` & `/ws` -> `SyncEventApplier` -> Room | Sync payloads carry `messageId`, `conversationId`, `userId`, `emoji`, `sticker.imageUrl`; malformed frames must rollback transaction without advancing cursor. |
| `StickerCacheManager` -> `filesDir/stickers/` | Cached PNGs belong to the active user session and must be verified against `SessionManager.getSessionKey()` before writing and wiped on logout/account switch. |
| Offline User Action -> `RealChatRepository` | Attempting Recall, Delete-for-Me, or Reaction while offline must NOT leave Room in a diverged phantom state (`D-12`). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-10 | Information Disclosure (Cross-Account Cache Leak) | `StickerCacheManager`, `Injection.cleanupDepartingSession` | medium | mitigate | Check `sessionManager.isSameSession(sessionKey)` before writing downloaded sticker PNGs or updating `StickerDao`; wipe `filesDir/stickers/` on `DISK` in `Injection.cleanupDepartingSession` alongside `pending_media`, `media_cache`, `camera`. |
| T-07-11 | Tampering (Malicious Sticker URL / Cache Path) | `StickerCacheManager`, `SendMessageWorker.executeStickerSend` | high | mitigate | Resolve every download URL strictly through `ApiClient.resolveBackendStickerUrl(BuildConfig.BACKEND_BASE_URL, imageUrl)` and sanitize `packCode`/`stickerCode` regex `^[a-z0-9_-]{1,50}$` before creating local file paths. |
| T-07-12 | Repudiation / State Desync | `RealChatRepository`, `SyncEventApplier` | medium | mitigate | Keep Recall/Delete-for-Me/Reaction strictly online-only (zero optimistic Room mutation on network failure -> return `ChatResult.error("NETWORK")`); apply server-confirmed sync events idempotently inside Room transactions. |
</threat_model>
