## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| On-disk Room SQLite (`utechat.db`) v3 -> v4 | Existing Phase 5/6 messages, FTS4 index, `attachment_transfer`, and `message_translation` rows must survive upgrade intact without data loss. |
| Server-supplied `sticker.imageUrl` -> `ApiClient.resolveBackendStickerUrl` -> OkHttp/Glide | Malicious or malformed relative URLs must never cause `AuthInterceptor` to send Bearer tokens to non-backend origins or traverse paths. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-07 | Tampering / Data Loss | `AppDatabase.MIGRATION_3_4` | high | mitigate | Implement explicit forward `Migration(3, 4)` matching Room entity SQLite schema 100%, attach alongside `MIGRATION_1_2` and `MIGRATION_2_3`, never call `fallbackToDestructiveMigration()`, and verify via `MigrationTestHelper` (`3->4` and `1->4`) against `4.json`. |
| T-07-08 | Information Disclosure (FTS4 Recalled Text Leak) | `MessageDao` | high | mitigate | `markRecalledByServerId` sets `text = NULL, normalized_text = NULL` (firing Room FTS4 update triggers) AND FTS4 search queries add `AND m.recalledAt IS NULL`; `Phase7RoomDaoTest` verifies recalled text yields 0 FTS4 hits. |
| T-07-09 | Information Disclosure (Bearer Token Exfiltration) | `ApiClient.resolveBackendStickerUrl` | high | mitigate | Enforce strict regex `^/api/stickers/assets/[a-z0-9_-]{1,50}/[a-z0-9_-]{1,50}\.(png|webp)$` and exact `scheme/host/port` comparison against `BACKEND_BASE_URL`. |
