<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted Android client -> `MessageController` | Client sends `messageId`, `conversationId`, and `ReactionRequest.emoji`. Identity comes strictly from `@AuthenticationPrincipal AuthenticatedActor` (`actor.userId()`). |
| `MessageService.recallMessage` -> `MediaService.prepareDownload` | Clearing `messages.attachment_id = NULL` alone would leave the attachment row unlinked and downloadable by the original uploader unless `attachments.revoked_at` is set atomically. |
| Backend JDBC -> Supabase `public` Schema (`V9`) | All 5 new tables (`sticker_packs`, `stickers`, `user_sticker_packs`, `message_deletions`, `message_reactions`) live in `public` and must have `ENABLE ROW LEVEL SECURITY` with zero public policies (ADR-007). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Elevation of Privilege | `MessageService.recallMessage`, `MessageService.toggleReaction` | high | mitigate | Enforce `sender_id.equals(actorId)` on recall (blocking even group `ADMIN`s -> `403 FORBIDDEN`), active membership (`left_at IS NULL` -> `403 NOT_A_MEMBER`), and 1-1 block check (`403 BLOCKED`) on both recall and reaction; lock message row `FOR UPDATE` before mutating. |
| T-07-02 | Information Disclosure (Recalled/Deleted Media Leak) | `MediaService.prepareDownload`, `MessageService.recallMessage` | high | mitigate | Set `attachments.revoked_at = now()` inside the recall transaction + schedule `TransactionSynchronization.afterCommit()` disk delete; check `revoked_at != null` BEFORE `linkedMsgs.isEmpty()` in `MediaService.prepareDownload` (`404 NOT_FOUND`); reject downloads of messages deleted-for-me by caller (`403 FORBIDDEN`). |
| T-07-03 | Information Disclosure (Cross-User Delete Leak) | `MessageService.deleteMessageForMe` | medium | mitigate | Emit `MESSAGE_DELETED_FOR_ME` strictly to `List.of(actorId)` so no other conversation participant receives or sees another user's private deletion. |
| T-07-04 | Tampering (Unicode/Emoji Injection & RLS Bypass) | `V9__message_actions_reactions_stickers.sql`, `MessageService.toggleReaction` | high | mitigate | Normalize `"\u2764"` -> `"\u2764\uFE0F"` (`"❤️"`), validate against exact 6-emoji allowlist in Java AND PostgreSQL `CHECK` constraint; enable `ROW LEVEL SECURITY` on all 5 new V9 tables with 0 public policies. |
</threat_model>
